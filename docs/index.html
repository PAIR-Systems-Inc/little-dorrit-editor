About these comparisons

Performance uses the same results as the Rankings tab. The 95% F1 intervals resample pages and runs; close scores may be indistinguishable. Rank alone does not establish a meaningful difference.

Token prices are a dated snapshot of standard uncached rates for the configured API route. OpenRouter listings are starting rates and can vary by provider. Missing quotes are excluded from price and value views. Source links and verification dates appear when you select a model.

The value chart estimates the text-token charge for 1 million input tokens plus your selected output volume. It is an illustrative workload, not measured cost per page. It excludes separate image charges, context-tier premiums, cache discounts, tools, and provider fees. Output includes any billed reasoning tokens. The frontier uses point estimates among the displayed, priced models; it does not account for uncertainty in F1.

The value chart uses a logarithmic cost axis: equal distances represent equal price ratios. F1 stays linear, from 0 to 1. Free models appear in a separate $0 column because zero has no logarithm; they still participate in the frontier comparison.

New benchmark runs retain provider-reported usage and cost. Historical runs without these records have unknown cost, not zero cost.

Benchmark routes and testing notes

Most models listed above were tested through OpenRouter, a unified interface for LLMs. The GPT models were also tested on the api.openai.com endpoint, so the OpenRouter versions are suffixed with "OR".

* Claude-family results use the same benchmark prompt, but the page images are resized and recompressed as needed to stay below Anthropic's 5 MiB per-image limit.

Reasoning-capable frontier models are evaluated at high reasoning effort. The selected effort is recorded in each model's experiment configuration.

The following observations from testing are not comprehensive.

  1. Claude-family models are marked with * on the leaderboard because their inputs are resized and recompressed to fit Anthropic's 5 MiB image limit before inference.
  2. Grok 2 Vision 1212 and OpenAI o1-pro continuously fail with errors in response indicating that a valid JSON was not returned. Error: 'NoneType' object is not subscriptable
  3. Phi 4 Multimodal Instruct and Qwen VL Plus repeatedly returned unparseable JSON: Error: Could not parse JSON from model response: Could not extract valid JSON from response: ...

About the Benchmark

Little Dorrit tests whether language models can read handwritten corrections on printed pages from Charles Dickens’ novel. Given a scanned page, each model identifies the edits and returns the original text, the intended correction, and its location as JSON.

Recognizing the words is only part of the task. The model also has to work out what change a caret, crossed-out phrase, or handwritten punctuation mark calls for.

How It Works

Required Fields

The model returns one entry for each correction, with these fields:

  • Type of edit: One of insertion, deletion, replacement, punctuation, capitalization, or italicize
  • Original text: The text as it appeared before the edit
  • Corrected text: The intended version after applying the edit
  • Line number: The line on which the edit occurs. Use line 0 for titles or headings, and start counting full lines of body text from line 1
  • Page: A known identifier for the image (e.g., "001.png"), provided alongside the input and not extracted by the model

Common editing marks include:

  • Insertions: Indicated by caret marks (^) or added words between lines
  • Deletions: Shown using strikethroughs or crossed-out text
  • Replacements: Circled, underlined, or bracketed text with substitutions nearby
  • Punctuation edits: Handwritten punctuation added, removed, or modified
  • Capitalization: Case changes marked explicitly or via notation
  • Italicize: Text that should be formatted in italics, typically indicated by underlining or special notation
